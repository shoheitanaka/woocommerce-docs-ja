# 製品アップデートのガイドラインとベストプラクティス

高品質で競争力のあるマーケットプレイスを維持するため、すべてのベンダーに定期的な製品のアップデートを推奨しています。一貫したアップデートは、WooCommerceとWordPressの最新バージョンとの互換性を確保し、セキュリティとパフォーマンスを向上させ、お客様に継続的な価値を提供します。

## ベストプラクティス

### TL;DR

[- 最低でも**6ヶ月ごと**に製品を更新してください。
- WooCommerceコアリリースカレンダー](https://developer.woocommerce.com/release-calendar/)に合わせてください。
- Quality Insights [Toolkit](https://qit.woo.com/) (QIT)や**ベンダーダッシュボード**などのツールを使用してください。
- [機能リクエストポータル](https://woocommerce.com/document/feature-request-portal/)をチェックして、製品のアイデアを探しましょう。
- 定期的なアップデート＝顧客の信頼と更新率の向上。

## なぜ定期的なアップデートが重要なのか

- **互換性**：製品が最新のWooCommerceとWordPressのリリースでシームレスに動作することを保証します。
- **セキュリティ**：脆弱性のパッチを適用し、お客様のサイトを安全に保ちます。
- **パフォーマンススピード、信頼性、効率を向上させます。
- **顧客の信頼**：ブランドと製品の寿命に対する信頼を築きます。定期的に更新される製品は、更新率が高くなります。アップデートのたびに、サブスクリプションを維持する価値を再認識できます。
- **サポート負荷の軽減**：積極的に問題に対処することで、サポートチケットの数を減らすことができます。

### 推奨事項

1. **[WooCommerceリリースカレンダー](https://developer.woocommerce.com/release-calendar/)**を監視してください：製品に影響を与える可能性のある変更を予測します。
2. **顧客からのフィードバックを活用するレビュー、サポートチケット、機能リクエストを使って、改善、新機能、コミュニティから要求された改善をお知らせします。
3. **セマンティック・バージョニング**を使用する：例例：機能には`v2.1.0`、変更点には`v3.0.0`を使用する。
4. **徹底的なテスト**：可能であれば、アップデートが安定しており、後方互換性があることを確認してください。潜在的な問題を自動的に検出するために、[Quality Insights Tool](https://qit.woo.com/docs/) (QIT)をワークフローに統合することを検討してください。
5. **変更を透明性をもって文書化する**：顧客向けの明確な変更履歴を維持し、必要に応じてドキュメントと製品ページを更新しましょう。

### 市場からの期待

WooCommerceコアの最新情報に更新されていない製品、および/または少なくとも6ヶ月に1回更新されていない製品は、WooCommerceマーケットプレイスから**削除フラグ**が立てられます。

### 推奨更新周期

[- **メジャーリリース**：WooCommerceのコアリリース](https://developer.woocommerce.com/release-calendar/)に合わせて、少なくとも四半期ごとにリリースします。
- **セキュリティ修正**：必要に応じて、緊急に。
- **マイナーな改善**：マイナーな改善**: 毎月、または機能や修正の準備ができ次第。
- **ドキュメント**：リリースごとに変更履歴とユーザーガイドを最新に保つ。

## アップデートの配布方法

### 新しいバージョンのアップロード

拡張機能の新バージョンをアップロードする前に、すべてのQIT品質基準に合格していることを確認することが重要です。これらのチェックは、ベンダーのダッシュボードから **_Quality Insights_** メニューオプションをクリックして実行できます。

[QITテストの詳細と実行方法](https://qit.woo.com/docs/)。

エクステンションがQITのチェックをすべて通過した後、更新版をアップロードすることができます。

バージョン**」タブをクリックします。過去にアップロードしたすべてのバージョンと、各バージョンのハイライトが表示されます。

![製品バージョンタブ](./_media/product-update-versions.png)

バージョン追加**ボタンをクリックしてください：

1. **あなたのコンピュータからアップロードしたい.zipファイル**を選択してください。
2. **バージョン番号**を追加します。
3.新しいバージョンを提出する**をクリックします。

送信されると、アップロードされたファイルに対して以下のテストが実行されます：

- [エンド・ツー・エンド](https://qit.woo.com/docs/managed-tests/woo-e2e) (E2E)
- [Activation](https://qit.woo.com/docs/managed-tests/activation)
- [Security](https://qit.woo.com/docs/managed-tests/security)
- [Woo API](https://qit.woo.com/docs/managed-tests/woo-api)
- [PHPC互換性](https://qit.woo.com/docs/managed-tests/phpcompatibility)
- [マルウェア](https://qit.woo.com/docs/managed-tests/malware)

すべてのベンダーの管理者は、プロセスを通じて、以下のような電子メール通知を受け取ります：

- **ベンダーの管理者は、新しいバージョンが提出されると、それがキューにあることを確認するEメールを受け取ります。何もする必要はありません。
- **不合格:** テストが不合格になった場合、ベンダーの管理者は具体的なエラーを含むメールを受け取ります。開発者はエラーの解決に努め、準備ができ次第新しいバージョンを提出してください。
- **自動テストに合格したバージョンは自動的にデプロイされ、顧客に提供されます。何もする必要はありません。

新しい製品バージョンを導入するには、アクティベーション、セキュリティ、およびマルウェアテストの合格が必要です。

#### 変更履歴のフォーマット

[変更ログのフォーマットとエントリータイプについての詳細](https://developer.woocommerce.com/docs/extensions/core-concepts/changelog-txt/#the-changelogtxt-file)。

#### よくあるエラー

アップロードに失敗した場合、まず確認すべき一般的なエラーがいくつかあります：

- **ファイル名:** WooCommerce.comはあなたの.zipファイルとその中のメインフォルダに特定の名前を探します。商品をアップロードしようとすると、予想される名前が表示されます：

![期待されるファイル名形式](./_media/product-update-filename.png)

- **変更ログが存在する**：`changelog.txt`という名前のファイルが、バージョンからバージョンへの変更点の記録として存在しなければなりません。
- **提供された `changelog.txt` ファイルは期待された形式と一致しません。
- **バージョンヘッダーが不一致です：拡張機能ヘッダのバージョンが、アップロード中に提供されたバージョンと一致しません。
- **拡張機能ヘッダーのバージョンと`changelog.txt`のバージョンが一致しません。

#### テスト結果の表示

自動テストの結果は **Submission Tests** テーブルに表示され、下図のように関連する **View** リンクをクリックすることで確認できます：

![テスト結果表示](./_media/product-update-test-results.png)

### プログラムによる新バージョンのアップロード

プログラムによって拡張機能をデプロイするには、拡張機能の更新でなければなりません。この方法は、ベンダーのダッシュボードにログインし、ユーザインタフェース (UI) を使用して同じアクションを実行する方法の代替となります。

#### アプリケーションパスワードの生成

1.WooCommerceベンダーダッシュボードにログインしていることを確認してください。
2.[アプリケーションパスワードを作成](https://woocommerce.com/wp-admin/authorize-application.php?app_name=WCCOM+Product+Submissions&app_id=c08e8963-897b-46cd-91e9-e92488ac9120).

:::note
追加のセキュリティのため、このアプリケーションパスワードはデプロイエンドポイントにスコープされ、ユーザーに代わって他のアクションを実行するために使用することはできません。
:::

#### 製品の展開

以下のコマンドを使用して、製品をデプロイするためのPOSTリクエストを行う：

```bash
curl -X POST https://woocommerce.com/wp-json/wc/submission/runner/v1/product/deploy \
  -F "file=@/path/to/zip" \
  -F "product_id=<product_id>" \
  -F "username=<username>" \
  -F "password=<app_password>" \
  -F "version=<product_version>"
```

`<product_id>`、`<username>`、`<app_password>`、`<product_version>`は、それぞれ実際のプロダクトID、ユーザー名、アプリケーションパスワード、製品バージョンに置き換えてください。

#### 配備状況の確認

デプロイのステータスを確認するには、以下のコマンドを使用する：

```bash
curl -X POST https://woocommerce.com/wp-json/wc/submission/runner/v1/product/deploy/status \
  -F "product_id=<product_id>" \
  -F "username=<username>" \
  -F "password=<app_password>"
```

#### ステータス・レスポンス

デプロイメント ステータスを照会すると、さまざまなテスト実行のステータスなど、進行状況に関する詳細がレスポンスで返されます。

以下はその回答例である：

```json
{
  "status": "queued",
  "version": "1.0.0",
  "test_runs": {
    "12345": {
      "test_run_id": "12345",
      "status": "success",
      "test_type": "activation",
      "result_url": "https://qit.woo.com/?qit_results=12345"
    },
    "67890": {
      "test_run_id": "67890",
      "status": "success",
      "test_type": "api",
      "result_url": "https://qit.woo.com/?qit_results=67890"
    }
  }
}
```

> 注：*** テスト実行オブジェクトは、実行されたテストタイプごとに 1 つずつ、レスポンス内に追加で存在する可能性があります。

### カスタム E2E テストによる互換性と信頼性の最大化

QIT の [カスタム E2E テストフレームワーク](https://qit.woo.com/docs/custom-tests/introduction) 上に構築された拡張機能の E2E テストを寄稿することを強く推奨します。これらのテストを私たちと共有することで、異なる WordPress や WooCommerce のバージョン、さまざまな PHP 環境、そして他の人気のある拡張機能との間で、真の互換性を確保する上で重要な役割を果たします。

当社のカスタムE2Eテストフレームワークは、Docker化された開発環境と使いやすいコマンドツールを備えており、[Playwright](https://playwright.dev/)を使用して、拡張機能独自の機能に合わせて包括的なテストを設計し、実行することができます。

このイニシアチブは、潜在的な互換性の問題がユーザーに影響を与える前に緩和するのに役立つだけでなく、私たちのマーケットプレイス内の製品の全体的な信頼性を向上させます。このプロセスに参加することは、堅牢なエコシステムに貢献するだけでなく、エクステンションの品質と信頼性に対する評価を高めることにもつながります。

[QITカスタム・テスト・ドキュメント](https://qit.woo.com/docs/custom-tests/introduction) をご覧いただき、カスタム・テストのパワーを活用して、拡張機能が実世界のシナリオでシームレスに動作し、競争の激しいマーケットプレイスで際立つことを保証してください。

## ヘルプが必要ですか？

アップデートの計画、QITのヘルプ、デプロイメントの問題など、お気軽にマーケットプレイスチームまでお問い合わせください。

WooCommerce.comマーケットプレイスの革新性、安全性、信頼性を維持するため、共に頑張りましょう！
